# Части системы и путь трека

```
игрок: экран радио или /syrradio add <ссылка>
   ↓
мод на сервере ──HTTP──► bridge: площадка → скачать → ffmpeg → ogg
   ↓            ◄──ogg──
рассылка кусками по 32 КБ через соединение игры
   ↓
мод на клиенте: проигрывает ogg звуковым движком игры
```

- **Мод, серверная часть** (`server/`) — список треков, режимы плеера,
  рассылка файлов, команды. Площадок не знает: всё скачивание — через bridge.
- **Мод, клиентская часть** (`client/`) — экран, проигрывание, клавиша.
  Клиент ходит только на свой сервер Minecraft, ни к площадкам, ни к bridge.
- **Bridge** (`bridge/`) — HTTP-сервис на Python рядом с сервером Minecraft.
  Знает площадки, качает, перекодирует, держит кэш на час.

Почему так:

- новая площадка — модуль в bridge, мод и клиенты игроков не меняются;
- у игроков не нужны ни аккаунты, ни подписки, ни VPN: качает сервер;
- ogg vorbis игра проигрывает сама — декодер в моде не нужен;
- трек скачивается целиком до старта, поэтому обрывы потока площадки до
  игроков не доходят.

Путь одного трека:

1. Игрок отправляет ссылку (`AddPacket` или команда).
2. Сервер спрашивает bridge `/resolve` — название, исполнитель, длительность —
   и ставит трек в список.
3. Когда трек становится текущим или следующим, сервер берёт файл `/audio`.
4. Файл уходит слушателям кусками; сервер назначает момент старта с запасом
   на докачку ([playback.md](playback.md)).
5. Трек доиграл — сервер сообщает bridge `/played`, сколько он реально играл.
