# HTTP API

Код: `bridge/app/main.py`. Все запросы, кроме `/health`, — с заголовком
`Authorization: Bearer <BRIDGE_TOKEN>`. Ошибка — JSON `{"error": "текст"}`,
текст показывается игроку как есть.

| Запрос | Ответ |
|--------|-------|
| `GET /health` | `{"ok": true, "sources": [...]}` — какие площадки включены |
| `POST /resolve {"url"}` | `source`, `native_id`, `title`, `artist`, `duration_ms`, `page_url` |
| `POST /audio {"url"}` | трек в ogg vorbis, заголовок `X-Duration-Ms` |
| `POST /played {"url", "seconds"}` | сколько трек реально играл |

- `/resolve` отказывает ссылкам на плейлисты и альбомы, не-ссылкам и трекам
  длиннее `MAX_DURATION_SEC`.
- `/audio` при первом запросе качает и перекодирует (10–20 с), повторные
  отдаёт из кэша. Один и тот же трек не качается дважды одновременно.
- `/played` для Яндекса отправляет отметку о прослушивании, как приложение;
  для остальных площадок ничего не делает.

Перекодирование (`audio.py`): стерео, 48 кГц, громкость выровнена `loudnorm`
(треки с разных площадок звучат одинаково), libvorbis `-q:a OGG_QUALITY`.
Без libvorbis (ffmpeg из Homebrew) — встроенный кодер, звучит хуже, годится
для проверки.

Кэш — папка `CACHE_DIR`, файлы живут `CACHE_TTL_SEC` с последнего запроса.
Медиатеку bridge не копит.
